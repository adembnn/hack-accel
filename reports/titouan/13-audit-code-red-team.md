# Audit du code contre le plan red team (#10) : wt-aiven et wt-decideurs

Audit en lecture seule, le 22 oct. 2026. Rien n'a été modifié, aucun `.env` lu, aucun appel payant.
Tests lancés : `node --test src/agents/*.test.mts` (51/51 verts), `node --test src/server/*.test.mjs` (20/20 verts, sur la base locale jetable du port 5434), `node tools/verif.mjs` dans les deux worktrees (tout vert : lint, typecheck, test, build, lot).
Termes : un **REX** est un retour d'expérience saisi par une enseigne. Le **vérificateur** refuse tout nombre absent du journal de simulation. « Contournement » = entrée exacte rejouée en local avec le vrai code.
Réserve : un test vert prouve le comportement testé, pas l'absence d'autres entrées qui passent (voir F1).
Numérotation : le test `securite.test.mjs` de wt-aiven appelle « A17 » le masquage des secrets, qui est **A18** dans le plan. Le vrai A17 (plan contre contraintes) n'a de test que côté decideurs.

## 2. Les 10 failles les plus graves

**F1. Le vérificateur de chiffres se contourne (A7, A8, A9).** Exploitation : le modèle (ou un cache falsifié) écrit `2.000 personnes sont sorties` : `Number("2.000")` vaut 2, présent dans le journal, donc accepté alors que le lecteur français comprend 2 000 ; idem `2 milliards`, `２００`, `٣٠٠٠`, `twelve thousand`, `septante`, `une douzaine`. Plus grave : la présence du nombre n'importe où dans le journal suffit (145 valeurs distinctes sur 20 minutes simulées ; 2, 7, 8 y sont, donc « 7 minutes » et « 8 portes fermées » passent, vérifié). Correctif : (1) refuser tout chiffre Unicode non ASCII et tout mot-nombre anglais, traiter `.` suivi de 3 chiffres comme séparateur de milliers, ajouter milliard/douzaine/moitié/septante/nonante ; (2) imposer des jetons `{{ref:J12}}` avec (zone, minute, métrique) et interdire tout nombre littéral dans la sortie, comme le plan l'exigeait ; (3) ne plus laisser `messages_par_zone` ni les clés du journal compter comme faits.

**F2. Promotion de leçon sans simulation, ouverte à tous (A3, A16).** Exploitation : `POST /api/lecons/statut {"id":1,"statut":"validee_par_simulation","runId":"<uuid>"}` ; les `run_id` se lisent par `GET /api/tableau` (sans filtre) puisque `tableau_commun.run_id` est renvoyé. Le CHECK exige un `run_validation` non nul, pas qu'il valide cette leçon. On peut aussi passer une leçon en `non_verifiee`, ou en `contradictoire`. Correctif : retirer cette route du serveur public (promotion réservée à un processus interne avec secret), exiger que le run soit `termine` et lié à la leçon (table `validations`), interdire par trigger toute transition vers `validee_par_simulation` depuis un autre rôle.

**F3. Aucune authentification : le tableau commun, les décisions et la provenance sont falsifiables (A4).** Exploitation : `POST /api/tableau {"auteur":"prefecture","genre":"alerte","contenu":{…}}` s'affiche en direct chez tous les clients SSE ; `POST /api/lecons {"sceneId":"forum","texte":"…","auteur":"corpus-public","provenance":{"auteur":"analyste","run_id":"…"}}` écrase la provenance (le serveur fait `{auteur,date,...provenance}`, le client gagne) ; `POST /rex` avec l'`enseigneId` d'une autre enseigne ; `POST /api/enseignes` réécrit nom et zone d'une enseigne existante (ON CONFLICT). Correctif : jeton par rôle (en-tête `Authorization`, valeurs en variables d'environnement), l'identité de l'enseigne déduite du jeton et non du corps ; ouvrir une connexion séparée avec `SET ROLE enseigne_ecriture` pour `/rex` (et supprimer `RETURNING *` pour ce chemin) ; écraser `provenance` côté serveur (`{...prov_client, auteur, date}` dans cet ordre).

**F4. Rien ne ferme vraiment la porte aux appels payants (A13).** Exploitation : `creerClientsDecision({autorise_payant:true})` ou `new RedacteurClaude({autorise_payant:true})` suffit, avec `DECIDER_BACKEND=jev-gateway` et la clé dans l'environnement ; `smoke-jev.mts` met `autorise_payant:true` en dur (protégé seulement par le drapeau `--oui-payant` et la présence de la clé). Plus risqué : `RedacteurClaudeCli` lance `claude -p` avec le prompt sur l'entrée standard sans `--allowedTools`/`--disallowedTools` ni répertoire isolé ; avec du texte de tiers dans le prompt (voir A2), un REX piégé pilote un agent qui a accès au disque et aux outils de l'utilisateur. Correctif : une seule fonction `autoriserPayant()` qui exige `MODE=reel` **et** un fichier jeton daté signé par Adem, appelée dans tous les constructeurs (jamais un booléen passé par l'appelant) ; pour la CLI, `claude -p --tools "" --disallowedTools "*"` dans un dossier vide, ou supprimer cette classe.

**F5. Un incident de connexion fait tomber le serveur et coupe le flux (disponibilité de la démo).** Exploitation : `ecouterTableau` (`db.mjs`) emprunte un client du pool pour `LISTEN` sans `client.on('error')` ; la coupure d'une connexion inactive côté Aiven émet `error` sur un objet sans écouteur, donc exception non rattrapée et arrêt du processus. Même sans crash, aucune ré-écoute après coupure : le SSE se tait. Le client d'écoute occupe aussi 1 des 5 connexions du pool. Correctif : écouteur `error` + `end` qui relance `LISTEN` avec reprise exponentielle ; connexion `pg.Client` dédiée hors pool ; ping `SELECT 1` périodique.

**F6. Secret de connexion dans stderr au démarrage, TLS non vérifié (A18).** Exploitation : une `DATABASE_URL` mal formée (mot de passe avec `@` ou `#` non encodé) fait lever `TypeError: Invalid URL` dans `ouvrir()` ; Node imprime la propriété `input` = l'URL complète, mot de passe compris (vérifié en local avec une fausse URL). `serveur.mjs` et `migrer.mjs` n'enveloppent pas cet appel dans le `masquer`. Ensuite `uselibpqcompat=true` chiffre sans valider le certificat (commentaire de `db.mjs`) : interception possible sur le chemin réseau, et rien n'impose `sslmode` hors base locale. `masquer` laisse passer une URL dont le mot de passe contient `/`. Correctif : `try { new URL(url) } catch { throw new Error('DATABASE_URL invalide') }` ; refuser toute URL sans `sslmode=verify-full` sauf `localhost` ; fournir le CA Aiven (`sslrootcert`) ; renforcer le motif de `masquer`.

**F7. Les REX posés par HTTP échappent au dédoublonnage et aux plafonds (A1, A10, A15).** Exploitation : 10 000 fois `POST /rex` avec le même corps : 10 000 lignes (pas d'`empreinte`, pas de limite de 20 REX par enseigne), double comptage des fréquences dans les leçons et saturation du stockage de la base gratuite. `personnesTouchees:100000` sans durée est accepté. Aucun plafond de débit par client. Correctif : calculer l'`empreinte` (sha256 sur enseigne, date, type, description) dans `validerRex`, refuser au-delà de 20 REX par enseigne et par jour (compteur SQL), exiger `dureeMinutes` quand `personnesTouchees` est fourni, ajouter un limiteur par IP.

**F8. SSE : saturation, trous, événements perdus (A12).** Exploitation : 100 connexions ouvertes qui ne lisent jamais (`curl -N` en boucle) remplissent `maxClients` ; aucun délai d'inactivité, un client dont `writableLength` reste sous 64 ko n'est jamais coupé, les 15 s de ping passent pour de l'activité. Après une coupure, la reprise lit `lireTableau` avec `limite` 200 : au-delà, le milieu est perdu sans alerte, puis les événements en direct (id plus grands) avancent `c.dernier`. Les `id` bigserial sont attribués avant le commit : deux écritures concurrentes peuvent notifier 6 puis 5, et `publier` écarte 5 (`id <= dernierId`). Correctif : durée de vie maximale par connexion (par exemple 10 min) et quota par IP, lecture de reprise en boucle jusqu'à vider l'écart, publication triée par un compteur `seq` dédié (ou `pg_notify` avec la ligne complète et lecture par `id > dernier`).

**F9. Cohérence plan/texte et A14 : contrôles faciles à tromper (A17, A14).** Exploitation : porte `saint_eustache` fermée au plan, le texte `Sortez par Saint-Eustache.` passe (comparaison avec `saint eustache`) ; `Fermez Lescot et sortez par Berger.` passe car `ferm` apparaît dans la phrase. Le contrôle ne lit que le dernier plan et ne connaît pas les contraintes dures (porte coupée feu). Les caches de rejeu (`fixtures/`) sont retrouvés par hash de la demande, la réponse n'est pas signée. Correctif : normaliser tirets et apostrophes en espaces avant comparaison, tester chaque porte par proposition (découpe sur virgule, « et », « mais »), valider le **plan** contre les contraintes (pas seulement le texte) ; stocker `sha256(réponse)` dans chaque entrée du cache et le recalculer à la lecture.

**F10. Schéma SQL et types TypeScript décrivent deux modèles différents.** Constats : `RexCrise` (TS : `id` texte, `enseigne`, `date`, `duree_min`, `mesures[]`, `efficace`) contre `rex_crises` (SQL : `id` bigserial, `enseigne_id`, `date_incident`, `duree_minutes`, `decisions_prises`, `resultat`, `lecons_enseigne`, pas de `mesures` ni `efficace`) ; `Lecon` (TS : `enonce`, `frequence`, `chiffres`, `zone`, `type_incident`, `sources` texte) contre `lecons` (SQL : `texte`, `etiquettes`, `confiance`, `rex` via `lecons_sources` en bigint) ; `Action.decideur` vaut `securite_centre|ugc|bspp` côté TS, alors que le commentaire de `decisions.decideur` annonce `securite` (colonne libre, aucun CHECK) ; `EntreeTableau` (minute, actions_acceptees, actions_refusees, lecons_utilisees) n'a pas de table correspondante : `tableau_commun.contenu` est un jsonb sans schéma ; `StockageTableau` n'est pas implémenté pour PostgreSQL ; les noms de champs sont en camelCase côté HTTP et en snake_case côté TS ; deux `validerRex` aux bornes différentes. Conséquence : le lot d'intégration devra écrire un adaptateur non testé, là où naissent les décalages silencieux (un champ perdu, un `statut` non transmis). Correctif : un schéma JSON unique (`contrats/rex.json`, `lecon.json`, `entree-tableau.json`) importé par les deux côtés, un `CHECK (decideur IN (…))` généré depuis `ACTEURS_CATALOGUE`, et un test aller-retour TS vers HTTP vers base vers TS.

## 3. Points vérifiés sans faille

- Injection SQL : aucune concaténation dans `db.mjs`/`serveur.mjs` (balayage du source + test).
- Fichiers statiques : sortie de `dist/` impossible (`%2e%2e`, `..%2f` testés).
- Appels réseau : seuls `fetch` de `redacteur.ts`, `jev.ts`, `jev-gateway.ts` (tous derrière `autorise_payant` + clé), `claude -p` (derrière `autorise`), et `tools/journal-push.mjs` (webhook Discord de `.env`, hors produit). Les tests remplacent `globalThis.fetch` et comptent zéro appel.
- Erreurs HTTP 500 génériques, `masquer` appliqué dans les deux `console.error` de `serveur.mjs`.
- Les clés ne sont jamais écrites dans les messages d'erreur (`Bearer` seulement dans l'en-tête).
